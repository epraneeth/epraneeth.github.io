Document retrieval · public prototype

Role-conditioned RAG

A local document-answering prototype that adapts query routing and rewriting to a selected professional role, then retrieves and reranks evidence before generation.

Explore the source

This is a public prototype, separate from my industry work. No empirical answer-quality or production-performance results are reported here. End-to-end setup remains to be verified.

From documents to an answer

  1. Uploaded PDF, text, or CSV content is extracted and split into chunks.
  2. BGE embeddings and Chroma provide dense retrieval.
  3. A role router and query rewriter condition the question. A cross-encoder reranks retrieved chunks.
  4. A local GGUF language model generates an answer. FastAPI exposes the backend; Streamlit provides the interface; SQLite stores chat records.

What needs separate evaluation

A list of retrieved filenames does not establish that each answer claim is supported. I want to measure retrieval relevance, answer support, citation accuracy, and appropriate abstention separately.

Role-conditioned prompting also does not provide access control. A shared deployment needs authorization before retrieval and per-user document boundaries. The current source should be understood as a local prototype.

Next experiment

Compare retrieval alone, query rewriting, and reranking on the same held-out questions. Keep the generator, corpus, and budgets fixed; record relevance, unsupported answers, latency, and failures. Establish the baseline before adding more agent components.
